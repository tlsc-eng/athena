# Keystroke cost of semantic tokens (October 2026)

v0.9 lays a language server's semantic tokens over the tree-sitter colours. The budget was that
typing must not get slower: keystroke-to-paint under 16 ms on a 2 k-line file, and no measurable
change from the tokens being there.

## Where the work happens

- The server's reply is parsed into JSON on the client's reader thread, as before.
- Reading the token numbers, splicing a delta into the previous data, decoding the relative
  encoding and mapping each token type to a colour run on the background executor
  (`decode_semantic` in `shell/lsp.rs`).
- Turning UTF-16 columns into byte offsets also runs on the background executor, against a
  snapshot of the rope (`place_semantic` in `lsp_ui.rs`). An answer for text that changed
  since it was asked is dropped and asked for again 300 ms after typing pauses.
- On the UI thread only two things remain: each edit moves the tokens after it by the edit's
  length (one pass of additions over the tokens below the cursor; tokens the edit reached across
  are dropped, one it fell inside is resized), and each paint merges the tokens of the painted
  byte range, found by binary search, into the tree's highlights with a stable sort (the list
  stays ordered for the minimap, and a semantic token paints over a tree range it equals).

## Method

Kept in the tree as an ignored test:

```
cargo test -p athena-editor --release --lib -- --ignored semantic_cost --nocapture
```

- Go files of 2 000 and 10 000 lines, one token per identifier (6 400 and 32 000 tokens).
- Per keystroke, as `keystroke_cost` measures: type one char (or Enter) in the middle of the
  file and compute the highlights of the 60 lines around the cursor, 760 keys per run. Without
  and with the semantic layer, each on a fresh buffer, twice, alternating.
- Apple M5, rustc 1.98.0, release profile. Two runs.

## Results

| Case | without tokens | with tokens |
|---|---|---|
| 2 k lines, keystroke + 60-line highlights, avg | 0.191–0.222 ms | 0.193 ms |
| 2 k lines, p99 | 0.228–0.419 ms | 0.229–0.232 ms |
| 10 k lines, keystroke + 60-line highlights, avg | 0.442–0.452 ms | 0.446–0.454 ms |
| 10 k lines, p99 | 0.481–0.537 ms | 0.486–0.543 ms |
| Decode and place all tokens (background executor) | — | 0.44–1.12 ms (2 k), 2.1–2.3 ms (10 k) |

The difference is within run-to-run noise at both sizes; after rebasing onto the minimap and
switching from appending to the stable-sort merge, a third run gave 0.196–0.203 ms (2 k) and
0.452–0.453 ms (10 k) with tokens against 0.190–0.209 and 0.442–0.443 without. The first version moved the tokens with
a clone-and-compact pass over every token from the cursor down; it measured 0.07 ms slower per
keystroke on the 2 k-line file and was replaced by the in-place shift above.

## Not covered

- Servers that answer with deltas: gopls 0.23 offers only full replies (and ranges), so the
  delta path is covered by unit tests, not by timing.
- The paint itself (shaping) is unchanged: semantic tokens change only the colour runs of
  lines already being shaped.
