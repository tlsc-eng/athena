# Athena v0.8 plan

## Context
v0.7.0 completed most VS Code-parity editor and git features. The v0.8 gap audit shows the largest remaining gaps are specific to working with Claude Code: reviewing a whole Claude session as one changeset, seeing Claude's plan and todos, resuming sessions, per-session cost, richer MCP tools, and the worktree/PR workflow Claude sessions rely on. Smaller LSP gaps round it out. Three file-disjoint lanes; same decision policy (VS Code defaults; reversible; stable Claude hook/MCP contracts — new tools and hooks are additive). Reading the user's own Claude transcripts (`~/.claude*/projects/**.jsonl`) for session lists/costs is in scope (read-only, local); tests use fixtures only.

## Lane x8-claude (Claude workspace)
1. Session changeset: a "Claude sessions" drawer tab listing recent Claude sessions per project (from Athena's snapshot store + transcripts), each expanding to every file the session touched with +/− counts; open one file's diff (DiffBase::Snapshot) or "Review all" stepping through files; "Revert file" (keeps a recovery copy) per file.
2. Plan and todos: hook `TodoWrite` and `ExitPlanMode` (PostToolUse matcher, additive to the existing hook set; installer stays idempotent and preserves user hooks) → `athena notify` → a per-terminal todo list shown in the Claude sessions tab and as a tab tooltip/progress badge (e.g. "3/7").
3. Session list and resume: read `~/.claude*/projects/<encoded cwd>/*.jsonl` for the active project (all known profiles: `~/.claude` and `~/.claude-*`), list sessions (first prompt, last activity, message count), "Resume" opens a new terminal tab running `claude --resume <id>` in the project root with the right CLAUDE_CONFIG_DIR.
4. Cost and tokens per session: sum transcript usage (input/output/cache tokens) per session; show tokens and an estimated cost using a small built-in price table keyed by model id (document that it's an estimate; prices editable in settings.json `claude.prices`).
5. MCP tools (additive): `lsp_definition`, `lsp_references`, `document_symbols` (live servers, unsaved buffers), `get_open_editors` (paths + dirty flag), `read_buffer` (unsaved text, size-capped), `run_tests` / `get_test_results` (wrapping athena-testing), `git_status`. Keep descriptions precise; cap outputs (frame limit).
Tests: transcript parser fixtures (resume ids, usage sums, malformed lines), hook installer idempotency with new matchers, MCP tool schemas + outputs, changeset listing from a fixture snapshot store.

## Lane x8-git (worktrees, GitHub, tests)
1. Worktrees: list/create (new branch or existing)/remove (refuse with uncommitted changes unless confirmed)/open as project (rail shows worktrees grouped under their main repo); palette + branch picker entries; safe git flags as everywhere.
2. GitHub via `gh` (only if installed and authenticated; never prompt): status-bar CI dot for the current branch (`gh run list --branch <b> -L1 --json status,conclusion,url`, refreshed on the autofetch timer or every 2 min while active), click opens the run; "Create Pull Request" (`gh pr create --web` — opens browser, no silent writes); "View PR checks" (`gh pr checks`). Tests mock `gh` with a fake script on PATH; never call real GitHub.
3. Go subtests runnable (`-run '^TestX$/^Sub$'` with proper regex escaping); ▶ marks for `t.Run("name", ...)` literal names.
4. Go coverage: "Run tests with coverage" → `-coverprofile` → covered/uncovered line tints in the gutter (toggle), cleared on edit of that file.
Tests: worktree ops in temp repos (incl. removal refusal), gh fake-script tests (not installed, unauthenticated, success, failure), subtest regex escaping, coverprofile parser.

## Lane x8-lsp (language features)
1. `workspace/willRenameFiles` + `didRenameFiles` on tree rename/move (apply returned WorkspaceEdit through the existing applier; dialog if edits touch > N files).
2. `completionItem/resolve`: documentation shown beside the completion list, resolved additionalTextEdits (TS auto-imports) applied on accept.
3. Per-project settings: `<project>/.athena/settings.json` (and read `.vscode/settings.json` for supported keys) layered over the global file; trust: project settings that change which programs run (lsp program paths, linters) require the per-project trust answer; documented.
4. Type hierarchy (Shift+Alt+H variant or palette), selectionRange (expand/shrink selection ctrl-shift-cmd-right/left like VS Code), rangeFormatting (Format Selection cmd-k cmd-f), linkedEditingRange for JSX/HTML tags.
5. Workspace trust for language servers: typescript-language-server loads the project's `node_modules/typescript` and tsconfig plugins → ask once per project (same trust store as linters) before using a project-local TypeScript; until allowed, run with the bundled/global typescript only (tsserver `typescript.tsdk` not set to project). gopls toolchain download: set `GOTOOLCHAIN=local` in gopls env unless the user's settings say otherwise.
6. Refactor lightbulb (not only quick fixes, behind setting default VS Code-like: show for quick fixes; refactors via cmd-.) and TS organize imports on save (setting `editor.codeActionsOnSave` subset: `source.organizeImports`).
Tests: gopls/tsserver-independent unit tests for each; gopls integration tests for willRenameFiles (gopls supports), selectionRange, type hierarchy where supported.

v0.8.0 via the runbook after lanes merge + visual QA findings fixed + review + fixes + docs.
