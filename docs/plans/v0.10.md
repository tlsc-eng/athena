# Athena v0.10 plan

## Context
v0.9.0 shipped the debugger, encodings, large files, minimap, semantic tokens, code lens and snippets. Feature coverage against VS Code is now broad. The two biggest remaining gaps are multiple windows and graphical settings and shortcut editors. Also, a large share of UI shipped since v0.2 has only test and log coverage and has never been seen on screen. v0.10 is therefore a stabilization milestone: two feature lanes plus a dedicated QA, performance and bug-bash lane. Decision policy unchanged.

## Lane x10-windows (multiple windows)
1. New Window (cmd-shift-n) opening an empty window, or a chosen project. Each window has its own rail (projects), layout and drawer. The same project can't be open in two windows: it focuses the other window, as VS Code does.
2. "Move Project to New Window" (rail context menu) and "Merge All Windows".
3. Persistence: workspace.json keeps per-window state (bounds, projects, active project). Migration from the single-window schema must not lose projects. Quitting saves all windows; launch restores all of them.
4. App-socket/MCP/CLI routing: `athena <folder>` opens in the focused window (or the window that already has the project); MCP tools resolve projects across all windows; notifications focus the right window.
5. Menus and shortcuts act on the key window. Daemon terminals and the Claude IDE server are shared app-wide.
Tests: workspace schema migration (old file to multi-window and back-compat read), routing tests, window-close semantics (closing the last window quits, as today; closing other windows keeps their projects' sessions alive and persisted).

## Lane x10-ui (graphical settings and shortcuts)
1. Settings UI (cmd-,): a searchable list generated from the settings schema (one source of truth shared with the JSONC template). Each setting shows title, description, a control (toggle, number, enum dropdown or text), "Modified" markers and a reset link, with User and Project scope tabs. Writes go through the existing comment-preserving writer. "Open Settings (JSON)" stays available.
2. Keyboard Shortcuts UI: a searchable table of every action with its binding, source (default or user) and `when` context. Recording a new binding by pressing keys detects conflicts and writes to keymap.json; reset a user binding; show when one of keymap.json's own entries is invalid.
3. JSON schema for settings.json and keymap.json, used by the JSON language server if one is present (a json-language-server is optional; never auto-install it). Built-in validation messages appear in the editor through Athena's own diagnostics for those two files.
Tests: schema/template consistency (every key documented, defaults match code), writer round-trips via the UI model, binding recorder conflict detection.

## Lane x10-qa (stabilize)
1. Visual QA sweep of the full check list in docs/ROADMAP-REPORT.md on the installed v0.9.0, idle-gated as before (≥ 300 s idle, unlocked screen, keys only, isolated HOME). File every defect with screenshots.
2. Perf re-baseline (E0 protocol from the original plan): 10 terminals plus Claude-like output, 2k/10k-line editors with semantic tokens, minimap and inlays on, git status on a large repo (clone the athena repo locally), memory over 30 min, thread and fd counts, idle CPU. Compare with docs/perf/2026-10-v0.2.md; fix regressions over 20 %.
3. Bug bash: fix everything found in 1 and 2 (separate commits), plus the open known gaps that are small: Claude Proposal diffs decode only UTF-8 (use the encoding module); a long completion detail is cut at its left edge; code lens re-requested after a trust Allow restart.
Tests: per fix; perf numbers recorded in docs/perf/2026-10-v0.10.md.

## Release
v0.10.0 via the runbook after lanes merge, then review, fixes and docs.
