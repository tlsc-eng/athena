# Athena v0.6 plan

## Context
v0.5.0 shipped IDE integration, multi-cursor, wrap and workbench polish. The refreshed gap audit (vs VS Code/JetBrains, for a Go/TS developer living in Claude Code) shows the biggest remaining daily gaps are: search power (find toggles, regex/globs/capture groups), configuring language servers (no settings file; gopls/tsserver options and inlay hints impossible), running tests from the editor, merge conflicts, and git remote ops. Three file-disjoint lanes; same decision policy (VS Code defaults; reversible; no protocol break with an older running daemon).

## Lane x6-search (athena-editor find + shell/search.rs + save pipeline)
1. Editor find bar: match case (alt-c), whole word (alt-w), regex (alt-r) toggles like VS Code; regex replace with $1 captures; invalid regex shown inline; match count "3 of 17".
2. Project search: same three toggles + "files to include"/"files to exclude" glob fields (globset, already in lock), `$1` replacement in regex mode (drop NoExpand only in regex mode), replace preview: per-file diff tab (reuse DiffView) before Replace All; keep result streaming/caps; results persisted per project while app runs.
3. Save pipeline: trim trailing whitespace + insert final newline on save (defaults: on for Go/TS/JS/Rust/Python/YAML/JSON/Markdown except trim off for Markdown — VS Code markdown keeps trailing double-space line breaks), `.editorconfig` support (indent_style/size, end_of_line, charset utf-8 only, trim_trailing_whitespace, insert_final_newline; nearest file wins, root=true stops), status bar LF/CRLF click converts line endings (one undo step).
Tests: regex/whole-word/case matrix incl. unicode word boundaries; glob include/exclude; $1 replacement; editorconfig resolution; trim/final-newline with multi-carets and CRLF.

## Lane x6-lsp (athena-lsp + shell/lsp.rs + editor LSP UI + settings)
1. settings.json in the app support folder (JSONC, watched like keymap.json, live reload, errors in a toast, "Open Settings (JSON)" palette/menu): editor (format_on_save, trim/final newline overrides, word_wrap, font size, tab size default), theme, ide_integration, and `lsp.<server>` sections passed to servers as `initializationOptions` and `workspace/configuration` answers (gopls: e.g. {"gopls": {...}}; tsserver preferences). Migrate the existing workspace.json toggles to read settings.json first (keep workspace.json fields as fallback; never lose a user's toggle).
2. Inlay hints (textDocument/inlayHint) rendered inline in muted text, toggle (settings + palette), on by default only if the server enables them via settings — ship sensible defaults for gopls (`hints`: parameterNames, assignVariableTypes off?) — choose VS Code Go extension defaults (all off) but make the toggle turn on a curated set; document.
3. documentHighlight: highlight other occurrences of the symbol under cursor (read vs write colours), debounce 250 ms.
4. Breadcrumbs row under the tab strip: path segments › symbol path (from documentSymbol), click a segment opens a dropdown (ContextMenu) of siblings/symbols.
5. Snippet tab stops: LSP completion snippets keep $1/${2:placeholder}/$0 as tab stops (Tab/Shift-Tab cycle, Escape exits, mirrored placeholders with same index edit together via multi-caret).
6. Grammars: go.mod/go.sum (if a tree-sitter grammar crate compatible with 0.27 exists; else line highlighter), Makefile, SQL, Protobuf — check crates.io + licence; fall back to line highlighters.
Tests: settings parse/merge/reload; workspace/configuration answers per section; inlay hint positioning with multi-byte; snippet tab-stop navigation; gopls integration tests for inlay hints + documentHighlight.

## Lane x6-run (tests, tasks, conflicts, git remote)
1. Test runner: Go (`go test -json` per package/test, run test at cursor via tree-sitter `func TestX(t *testing.T)` detection + gutter ▶ run marks) and JS/TS (vitest/jest JSON reporters when configured in package.json); results: gutter pass/fail dots, a "Tests" drawer tab with tree (package › test), failure output with clickable file:line, re-run failed. Reuse the Playwright crate pattern; run in a background process with time limit, cancellable.
2. Task runner: package.json scripts and Makefile targets listed in palette ("Run Task…"), run in a new terminal tab in the project root.
3. Merge conflicts: highlight conflict markers in the editor (current/incoming/base colours), inline "Accept Current | Accept Incoming | Accept Both | Compare" actions above each block (VS Code CodeLens-style row), a conflicts count in the Changes tab; after resolving all blocks, Stage offers itself.
4. Git remote: fetch (periodic every 3 min while active, like VS Code autofetch default off? → VS Code default is off; ship off with a setting), pull (--ff-only by default), push (with upstream set-up prompt), ahead/behind in the status bar branch cell; stash push/pop/list in the branch picker.
Tests: go test -json parser fixtures (pass/fail/skip/panic/output), test detection, task discovery, conflict block parser + accept transforms (incl. CRLF, nested markers refusal), git remote ops in temp repos with a bare remote.
