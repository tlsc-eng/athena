# Athena v0.5 plan

## Context
v0.4.0 closed the daily-use gaps found in the v0.4 gap audit (editing ergonomics, navigation, LSP edits, diff/commit, Claude edit review). The remaining high-value gaps (docs/ROADMAP-REPORT.md backlog, docs/plans/claude-ide.md) are: first-class Claude Code IDE integration (approve edits in a diff, live selection context), multi-cursor editing and word wrap, and workbench polish (exact session restore, recent projects, user keymap, light theme, shell-integration command marks). Three file-disjoint lanes; same decision policy (VS Code defaults; reversible; no protocol break with a running older daemon).

## Lane x5-ide — Claude Code IDE integration (docs/plans/claude-ide.md)
Scope exactly as the spike's "What Athena would need" items 1–8, with these decisions for its open questions:
- Setting `ide_integration` default **off** for this release (palette + File menu toggle; README documents it). Reversible; protocol drift risk.
- Port reaches shells WITHOUT a mux protocol change: the GUI writes `<data_dir>/ide.env` (`CLAUDE_CODE_SSE_PORT=<port>`, `ENABLE_IDE_INTEGRATION=true`) atomically, mode 0600; athena-mux reads it when spawning a pane and adds those two vars after env_clear (allowlist extension, no PROTO_VERSION change). Stable port across GUI restarts: try to rebind the previous port first (stored in ide.env), else new port and rewrite; panes keep working via cwd matching per the spike.
- `openDiff`: reuse DiffView in a "proposal" mode (old = file on disk, new = Claude's proposed text), Accept (`cmd-enter`) / Reject (`cmd-backspace` or close) → reply `FILE_SAVED`+contents / `DIFF_REJECTED`; on Accept do NOT write the file ourselves unless the spike's open question 2 is resolved by a live test with a stub/recorded CLI — if unresolved, follow claudecode.nvim's behaviour (document which).
- Quit/crash: answer pending diffs `DIFF_REJECTED` and remove the lock file (also in the panic hook path).
- Security: loopback only, 0600 lock in 0700 dir, constant-time token compare, refuse requests with an Origin header, per-connection rmcp session; unknown tools → clean MCP error.
- Tests: recorded-frame fake client (handshake, auth failure, Origin refusal, openDiff accept/reject, selection_changed debounce, getDiagnostics uri echo), lock file lifecycle, ide.env read by mux spawn (daemon test).

## Lane x5-edit — multi-cursor and word wrap (athena-editor)
1. Multiple cursors: `Cursor` → `Vec<Selection>` with a primary; every edit op applies to all selections in reverse order as one undo step; merge overlaps. Bindings (Editor context, VS Code macOS): `cmd-d` add next occurrence (Editor context only — terminal/pane `cmd-d` split stays; document), `cmd-k cmd-d` skip, `cmd-shift-l` select all occurrences, `alt-click` add cursor, `cmd-alt-up/down` add cursor above/below (check conflicts — FocusPane uses cmd-alt-arrows → if taken in Shell context, Editor context shadows only while editor focused; decide and document), `shift-alt-drag` column select, Escape collapses to primary. Completion/auto-pairs/line ops/indent work per cursor or fall back to primary with documented exceptions.
2. Word wrap (`alt-z`, per-editor toggle + workspace default off; Markdown default on like VS Code): soft wrap through DisplayMap (folds + wraps share the row mapping), wrap at viewport width, wrapped-line indent, cursor up/down by visual row, Home/End on visual lines (VS Code behaviour), gutter shows number on first row only.
3. Sticky scroll (enclosing scopes pinned at top, from tree-sitter/fold regions) — only if 1–2 land solid.
Tests: multi-cursor op matrix (insert, delete, newline, paste N lines into N cursors, undo/redo), occurrence search unicode/case, wrap row mapping with folds, cursor movement across wrapped rows; perf: 10k cursors-free path unchanged (2k-line keystroke budget).

## Lane x5-bench — workbench polish (shell, workspace, term, ui)
1. Session restore fidelity: persist per editor item cursor (UTF-16), scroll top line, folds; restore on launch (schema change with serde defaults).
2. Open Recent: recently closed project roots (cap 20) in palette mode + File menu (`ctrl-r` like VS Code macOS if free).
3. User keymap: `~/Library/Application Support/athena/keymap.json` (VS Code-like `[{key, command, when}]` with Athena action names and contexts), loaded after defaults, reloaded on change via the watcher; invalid entries reported in a toast; "Open Keyboard Shortcuts File" palette command; README section.
4. Light theme + "follow system appearance" (default: follow system): full token set incl. terminal palette (light variant tuned for Claude Code readability), syntax colours, preview CSS; switch live on NSApp effectiveAppearance change.
5. Shell-integration marks in the terminal: athena-term scans OSC 133 A/B/C/D in the byte stream before feeding alacritty (no daemon change), records prompt/command/exit marks per line, draws a thin gutter dot (success/failure colour) and supports `cmd-up`/`cmd-down` jump to previous/next prompt (check conflicts in Terminal context), plus "copy last command output".
Tests: persistence round-trip with old files; keymap parsing/merging/conflict reporting; theme token completeness (every token present in both themes; contrast checks for text/ANSI on both backgrounds); OSC 133 parser incl. split sequences across chunks.

## Release
v0.5.0 via the runbook after all lanes merge green + a correctness review pass + fixes; update README and docs/ROADMAP-REPORT.md (v0.5 section).
